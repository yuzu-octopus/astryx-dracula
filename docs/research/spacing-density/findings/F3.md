## Conflicting evidence
- Apple 44pt default vs WCAG AA 24px: Apple stricter; WCAG-AA-only violates Apple default. No conflict at AAA (both 44).
- Apple iOS minimum 28pt vs WCAG AA 24px: 24-27px zone passes WCAG, fails Apple minimum.
- visionOS 60pt hit + 60pt center spacing vs WCAG AAA 44: visionOS stricter.
- Ant small ~38px derived row passes WCAG height only if inner targets meet 24px or spacing exception; custom 30px rows = fail pattern.
- Practitioner lore 32px compact rows vs Atlassian/Salesforce primaries: neither specifies fixed compact row px; 32px unverified, never cite as official.
- pt vs CSS-px: Apple pt, WCAG CSS px; compare valid ~1x only. No primary gives conversion; keep units separate.

## Gaps
- Apple HIG: no universal spacing scale (4/8/12/16/24/32 starter is not HIG mandate) — unverified as Apple requirement.
- Apple HIG: no list/table row-height px, no text-field height px; only API default NSTableView 16.0 + button scale 28/32/44/52/64.
- Atlassian compact row px absent; 36-40px only derived.
- Salesforce compact row px absent; sm/md padding labels only.
- macOS 20pt minimum control vs WCAG 24px: sub-24 macOS controls rely on Spacing exception; no Apple primary bridges this.

## Summary
- Apple: 44pt hit default (60 visionOS); mins 28 iOS / 20 macOS / 56 tvOS / 28 visionOS-watchOS.
- Spacing matters: 12pt bezelled, 24pt unbezelled; tvOS safe 60/80; widgets 16, tight 11.
- HIG sets no table row px, no field height px; only NSTableView default 16.0 + button scale 28/32/44/52/64.
- WCAG AA 2.5.8 = 24x24 CSS px + 5 exceptions + circle-spacing test; AAA 2.5.5 = 44x44.
- Apple 44 aligns AAA, beats AA; 24-27px zone passes WCAG, fails Apple.
- Dense tables: only Ant gives hard tokens (block 16/12/8 => ~54/46/38px); Atlassian/Salesforce give no fixed row px.
- Never cite 32px compact row as official; mark derived numbers speculative.

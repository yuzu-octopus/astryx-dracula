1. **Core exposes no `data-*` STATE hooks anywhere — file it as a general condition, not as a `CommandPaletteItem` patch. Precise form: `data-*` only, NOT "no state attributes".** `CommandPaletteItem` (emits `aria-selected` / `aria-disabled` / `data-value`, no `data-selected`, no `data-highlighted`) is the *first-noticed instance*, not the defect. J1's search list was `data-*` only, so "core emits zero state attributes" is TRUE for `data-*` and FALSE as stated. F5 §J1 should correct its own claim; this file no longer repeats it.
   **The consequence, stated correctly: the kit cannot target interactive state from `tokens.css` by `data-*` anywhere**, even though the styling doc's "Preferred Selector Surface: Data Attributes" section names `data-*` as the sanctioned surface — so the kit follows the documented rule and cannot comply.
   **And for selected table rows, the blocker is PER-PROPERTY, not per-element — measured.** `useTableSelection.tsx:131` sets `el.style.backgroundColor = selectedBgColor` (`:279` → `colorVars['--color-accent-muted']`, whose *declared* value is `light-dark(#0082FB33, #0082FB3F)`, `theme/tokens.stylex.ts:26`). An inline declaration outranks any `tokens.css` rule **for that property only**. Measured across `core/src` (tests excluded): `style.backgroundColor` inline assignments = **2** (both this function); `style.boxShadow` = **0**. `background-color` and `box-shadow` are independent properties, so **a ring (`box-shadow`) on a selected row is NOT blocked** and `--shadow-inset-selected` ships as-is — no `!important`, no core change, no version bump. **The one real blanket case: a kit `background-color` wash on a selected table row IS unreachable** (would need `!important`, banned by the zero-`!important` gate, or a core change, deferred by the version ruling).

# F6 — Systematic candidate-hex sweep

**This is a documented candidate set for human review. It is NOT a recommendation to add any of these.**

Nothing below is an endorsement. Rows are grouped by the UI job the source file itself gives the colour, so a reviewer can accept or reject per hex. No styling advice, no adoption ranking.

---

## Method

**Corpus.** 514 repositories under the `dracula` GitHub org, shallow-cloned (`git clone --depth 1`) into `/tmp/drac` on 2026-09-28. Repository list came from the GitHub org API (`https://api.github.com/orgs/dracula/repos`, pages 1–2, then HTML scrape of `/orgs/dracula/repositories` after the API rate limit hit). 198 of the 514 are Dracula-specific (name contains `dracula`, or the repo ships a file whose basename contains `dracula`).

**Harvest.** Every `#`-prefixed hex literal in every text file, plus every bare 6-digit hex used as a quoted XML/JSON/YAML value (this second pass is what catches `jetbrains/.../Dracula.xml`, which stores colours as `value="48b764"` with no `#`). 3- and 4-digit literals are expanded; 8-digit literals are kept whole because the alpha channel is itself the datum.

**Diff.** Against the 29 shipped hexes. 23 of the 29 appear in the ecosystem corpus; 6 do not (`#4C5067 #8288A6 #8C939B #9AA1BC #B0B3C4 #FFD5CC` — all kit-local, not ecosystem values).

**Inclusion rule (auditable).** A hex is a candidate iff it satisfies at least one of:

- **R1 — spec-sanctioned.** Appears in `dracula/spec/dracula-spec.md`.
- **R2 — first-party theme definition.** Appears in a Dracula theme-definition file inside the org (the CANON list: spec, visual-studio-code, cursor, base16-dracula-scheme, alacritty dracula/snazzy/omni/plus, kitty, windows-terminal, hyper, tilix, xresources, termite, termux, gnome-terminal, telegram, sublime, textmate, jetbrains, dracula-css, vim, obsidian, emacs, slack, terminator, oh-my-posh, nova, zed).
- **R3 — port consensus.** Appears in ≥2 Dracula-specific repos of the 198.

Result: **254 candidates**. Of these, **90 are already derivable** from an existing `--color-data-*` ramp (same hue ±8°, same saturation ±15 pts, same lightness ±5 of one of L=28/44/60/74/88) and **164 are not**.

**Exclusion rule.** A hex appearing only in a repo that bundles non-Dracula themes or is a general application (ConEmu, x64dbg, fontforge, gimp, blender, jupyterlab, django-admin, monoDevelop, …) is **not** a candidate. `dracula/alacritty-theme` is a mirror of alacritty's entire theme set (2 077 non-Dracula hexes); only its `dracula.toml`, `dracula_plus.toml`, `snazzy.toml`, `omni.toml` were read.

**Derivability test.** HSL of the candidate compared against the nine shipped ramp bases — `purple hsl(264.71 89.47%)`, `pink hsl(325.52 100%)`, `red hsl(0 100%)`, `orange hsl(31.02 100%)`, `yellow hsl(64.91 91.67%)`, `teal hsl(190.53 96.61%)`, `blue hsl(225.45 26.61%)`, `shamrock hsl(135.18 94.44%)`, `gray hsl(231.43 14.89%)` (`tokens.css:269-313`) at L=28/44/60/74/88. Thresholds dH≤8, dS≤15, dL≤5. Neutrals (S<8) are judged against the gray ramp alone.

**Confidence legend.** `spec` = in the official spec's own tables. `first-party` = in a dracula-org theme-definition file. `consensus` = R3 only, ≥2 Dracula ports. `single` = one file, no second witness. `inherited` = present in the file but not authored by Dracula (see Conflicts).

## Conflicting evidence

1. **Two different "bright red/green/yellow/magenta" sets, both shipped under the Dracula name.** The spec's `AnsiBright*` (`spec/dracula-spec.md:60-68` → `#FF6E6E #69FF94 #FFFFA5 #FF92DF`) vs the Snazzy set (`hyper/index.js:15-19` → `#FF6E67 #5AF78E #F4F99D #CAA9FA #FF92D0`), used by 7 org ports. The spec set wins: it is the only one the spec names, and `spec/dracula-spec.md:76` names `dracula/visual-studio-code` — which uses the spec set (`dracula.yml:31-35`) — as *the* compliant implementation. Snazzy is a fork's choice.

2. **The same ANSI slot, four different values across first-party ports.** Bright black: `#6272A4` (spec:58) · `#4D4D4D` (hyper:14, xresources:5, termite:16, tilix:21) · `#555555` (alacritty dracula.toml:21) · `#7A7A7A` (gnome-terminal:9). These are *not* variants of one another — they span 25 lightness points. The disagreement is over what "default foreground for dim text" means, and the spec does not say.

3. **The IDE port's colours are largely not Dracula's.** `jetbrains/…/Dracula.xml` declares `parent_scheme="Darcula"` (line 1). Values like `#48B764`, `#CD4644`, `#74B4C1`, `#EF233C`, `#F8961E`, `#ABC4FF`, `#FF0000`, `#CD4848`, `#FFF3B0` are Material/Darcula defaults restated in the file, not Dracula choices — `#EF233C` is Material Red 500 and `#F8961E` is Material Orange 500. **These should not be read as ecosystem intent.** The values that *are* Dracula-authored in that file are the ones sitting on Dracula-named keys: `FILESTATUS_DELETED` → `#FF6E6E` (line 15), `FILESTATUS_IGNORE.PROJECT_VIEW.IGNORED` → `#9A9A9A` (line 24), and the console `FOREGROUND`/`BACKGROUND` pairs for the four spec brights (lines 145-194). The JetBrains *new colour schema* layer (`Dracula.theme.json`) is fully Dracula-authored and is the more reliable JetBrains evidence.

4. **Foreground drift: `#F8F8F2` (spec) vs `#F8F8F0` (6 ports).** `sublime/Dracula.tmTheme:27,394,407`, `textmate/Dracula.tmTheme:28,328,341`, `atom/styles/colors.less:17`. A 2/255 difference on the blue channel. Not derivable from the ramp (it is a warm near-white, not a yellow step) and not the spec value.

5. **Background drift: `#282A36` (spec) vs `#282936` (base16, Tilix) vs `#191622` (Omni) vs `#212121` (Dracula Plus).** The base16 and Tilix drift is 1 hex unit on blue. The Omni and Plus variants change the background outright, which makes them different themes rather than variants.

6. **Caret colour is unspecified by the ecosystem.** `spec/dracula-spec.md` has no cursor token. Ports use `#F8F8F2` (kitty:51, xresources implicit, wezterm), `#CCCCCC` (jetbrains/Dracula.xml:7), `#F8F8F0` (sublime:27), `#ECEFF4` (dracula_plus.toml:9). Four values, no authority.
